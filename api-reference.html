Authentication

2 endpoints
POST /auth/login Authenticate user, return token

Validates username, password, and role. Role must match the account's configured role — an employee cannot log in as a manager. Returns the authenticated user profile and a bearer token.

Request Body
username string password string role enum // Employee | Manager | Hr
Response 200
token string // JWT bearer token user object id string displayName string email string role enum managerLevel string? // "L1" | "L2" jobTitle string entity string department string
POST /auth/logout Invalidate session token

Invalidates the bearer token server-side. The client discards the token from local state on a successful response.

Request Body
// None — token read from Authorization header
Response 204
// No content

Overtime — Employee

Employee 2 endpoints
GET /overtime/employee/{empId} Employee's own OT submissions

Returns all overtime records submitted by the given employee for the requested month. Used in both the "Overtime Requests" calendar page and the "My Requests" history page. Returns all statuses — the UI filters by tab.

Query Params
year number // e.g. 2026 month number // 1–12
Response 200
OTRecord[]
POST /overtime Submit a new OT request

Employee submits an overtime request for a specific date. Server sets employee_submit_status = 'Submitted' and l1_approval_status = 'Pending'. Duplicate submissions for the same employee + date must be rejected with 409 Conflict.

Request Body
empId string date string // "DD Mon YYYY" clockIn string // "HH:MM" clockOut string reason string preApproved boolean employee_submitted_hours regularDayOT number regularDayOTAfter9PM number publicHolidayOT number total number
Response 201
OTRecord // full record as stored

Overtime — L1 Line Manager

L1 Manager 5 endpoints
GET /overtime/manager/{managerId} Team OT records for L1 manager

Returns all overtime records from the manager's direct reports for the requested period. Includes Pending, Approved, and Rejected records so the manager can review the full history for the month.

Query Params
year number month number // 1–12
Response 200
OTRecord[]
PATCH /overtime/l1/approve-bulk Bulk approve multiple OT records

Approves all specified records using submitted hours as approved hours. Records whose l2_approval_status is null are automatically advanced to 'Pending' so they appear in the HoD queue.

Request Body
recordKeys string[] // "empId|date" l1ManagerName string
Response 200
OTRecord[] // updated records
PATCH /overtime/l1/reject-bulk Bulk reject multiple OT records

Rejects all specified records with a shared comment stored in l1_comments. Clears l2_approval_status to null — rejected records do not proceed to HoD.

Request Body
recordKeys string[] // "empId|date" comment string
Response 200
OTRecord[]
PATCH /overtime/{empId}/{date}/l1/approve Approve single with custom hours

Approves a single record and allows the L1 manager to override the hours (e.g. reducing 5h submitted to 3h approved). The adjusted hours go into l1_approved_hours, preserved separately from employee_submitted_hours.

Request Body
regularDayOT number regularDayOTAfter9PM number publicHolidayOT number totalOTApproved number l1ManagerName string l1_comments string // optional note
Response 200
OTRecord
PATCH /overtime/{empId}/{date}/l1/reject Reject single with comment

Rejects a single record. l1_comments is required and must be specific enough for the employee to understand the decision. L2 status is reset to null.

Request Body
l1_comments string // required regularDayOT number regularDayOTAfter9PM number publicHolidayOT number totalOTApproved number
Response 200
OTRecord

Overtime — L2 Head of Department

L2 HoD 3 endpoints
GET /overtime/hod/{hodId} Records awaiting or reviewed by HoD

Returns OT records for all employees under the HoD's department that have been approved by L1 (l1_approval_status = 'Approved'). Includes both Pending and already-actioned L2 records so the HoD can see the full picture for the period.

Query Params
year number month number // 1–12
Response 200
OTRecord[]
PATCH /overtime/l2/approve-bulk Bulk approve by HoD

Final approval stage. Records approved here become visible in the HR payroll export. Sets l2_approval_status = 'Approved' and records the HoD's name in l2ManagerName.

Request Body
recordKeys string[] // "empId|date" l2ManagerName string
Response 200
OTRecord[]
PATCH /overtime/l2/reject-bulk Bulk reject by HoD

HoD rejects records with an optional comment stored in l2_comments. Rejected records are not included in the HR payroll export.

Request Body
recordKeys string[] // "empId|date" comment string? // optional
Response 200
OTRecord[]

Overtime — HR

HR 2 endpoints
GET /overtime/hr Fully approved records for payroll

Returns only records where both l1_approval_status and l2_approval_status are 'Approved'. Supports optional filtering by entity and department. Used by both the HR Approvals page and the payroll export.

Query Params
year number month number // 1–12 entity string? // filter by entity department string? // filter by dept
Response 200
OTRecord[]
GET /overtime/hr/export Download payroll CSV

Returns a CSV file of all fully-approved OT records for the period, with calculated pay columns. The current implementation generates this client-side from the /overtime/hr response — the server endpoint is an alternative to offload the calculation.

Query Params
year number month number
Response 200
Content-Type: text/csv Content-Disposition: attachment; filename="overtime-payroll-{month}-{year}.csv"

CSV columns: Emp ID, Name, Grade, Date, Reg OT Hrs, Non-Reg OT Hrs, Holiday OT Hrs, Total OT Hrs, L1 Approver, L2 Approver, Reg OT Pay (AED), Non-Reg OT Pay (AED), Holiday OT Pay (AED), Total OT Pay (AED).

Attendance

Employee L1 Manager 1 endpoint
GET /attendance/{empId} Monthly attendance records

Returns a day-by-day attendance log for the requested month. Each record includes the day's status, clock-in/out times, total hours, and a flag indicating whether an approved or pending OT record exists for that day.

Query Params
year number month number // 1–12
Response 200
AttendanceRecord[] date string day number dayOfWeek string status enum // Present|Weekend|Leave|Holiday clockIn string? clockOut string? totalHours number? hasOT boolean? otStatus string?

Shifts & Leave

Employee L1 Manager 4 endpoints
GET /shifts/{empId}/details Monthly shift + OT schedule

Returns a day-by-day breakdown of shift times and OT for the month. Workday records include shift start/end, duration, OT hours, OT start/end times, and total expected hours. Weekend records are returned with isWorkday: false and no time fields.

Query Params
year number month number
Response 200
ShiftRecord[] date string isWorkday boolean shiftStart string? shiftEnd string? shiftDurationHrs number? otHours number? otStatus string? otStartTime string? otEndTime string? totalExpectedHours number?
GET /shifts/{empId}/info Shift window for a period

Returns the employee's fixed shift window (start and end time) for the given month. Used when rendering the attendance calendar to show what "normal" hours look like for an employee vs their actual clock-in/out.

Query Params
year number month number
Response 200
startTime string // "HH:MM" endTime string // "HH:MM"
GET /shifts/team/{managerId} Full team shift plan for manager

Returns the full month shift plan for all of the manager's direct reports, keyed by employee ID. Used by the Shift Plan page so the L1 manager can view and record OT hours for the entire team on one screen.

Query Params
year number month number
Response 200
// keyed by empId Record<string, ShiftRecord[]>
GET /leave/{empId} Employee leave days for a month

Returns which calendar days the employee is on approved leave. Used to mark leave days on the attendance calendar and to prevent the employee from submitting OT requests on leave days.

Query Params
year number month number
Response 200
leaveDays number[] // day-of-month e.g. [3, 17]
